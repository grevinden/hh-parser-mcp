# Режим приложений FastMCP: интерактивные инструменты

> Раздел отвечает на вопросы: что такое «режим приложений» (apps mode),
> чем UI-инструмент отличается от обычного инструмента, как передаются
> параметры, кто кого вызывает и как вызывать hh-mcp из другого приложения
> по API.

---

## 1. В двух словах

Обычный MCP-инструмент (например, `get_vacancy`) принимает JSON-аргументы и
возвращает текст. Его вызывает модель (LLM) или внешний клиент.

**Режим приложений (apps / Interactive Tools)** — это способ превратить
инструмент в **интерактивную страницу в браузере**: формы, кнопки, поля ввода,
таблицы, графики. Такой инструмент возвращает не текст, а **дерево UI-компонентов**
(Prefab), которое хост (клиент MCP с поддержкой приложений) рендерит как
живой интерфейс. Пользователь видит приложение и работает с ним мышью.

В hh-mcp это реализовано через `FastMCPApp` — обёртку, которая разделяет
инструменты на две роли:

| Роль | Декоратор | Что делает | Кто вызывает |
|---|---|---|---|
| **UI-точка входа** (entry point) | `@app.ui()` | Возвращает дерево компонентов — открывает панель в браузере | Модель / клиент |
| **Backend-инструмент** | `@app.tool()` | Собственно выполняет работу, возвращает данные | UI (через `CallTool`), модель — только при `model=True` |

Подход описан в официальной документации FastMCP:
[gofastmcp.com/apps/fastmcp-app](https://gofastmcp.com/apps/fastmcp-app).

## 2. Как это устроено в hh-mcp

В `src/hh_mcp/app.py` зарегистрированы 4 инструмента:

- **`get_vacancy(id)`**, **`get_employer(id)`** — backend-инструменты с
  `@app.tool(model=True)`: видны и модели, и UI. Принимают `id` и возвращают
  Markdown страницы hh.ru.
- **`vacancy_app()`**, **`employer_app()`** — UI-точки входа с `@app.ui()`:
  принимают **ноль** параметров и возвращают панель с полем ввода и кнопкой.
  Кнопка внутри панели через `CallTool` вызывает backend-инструмент.

Связка для `vacancy_app`:

```python
@app.ui()
def vacancy_app() -> Column:              # 1. Модель вызывает vacancy_app()
    id_input = Input(placeholder="ID вакансии…", name="vacancy_id")  # 2. Поле ввода
    return Column(
        children=[
            Heading("Просмотр вакансии"),
            id_input,
            Button(
                "Получить вакансию",
                on_click=CallTool(
                    tool="get_vacancy",               # 3. Кнопка → get_vacancy
                    arguments={"id": "{{ vacancy_id }}"},  # 4. id берётся из поля
                    on_success=ShowToast("Готово", variant="success"),
                    on_error=ShowToast("Ошибка", variant="error"),
                ),
            ),
        ],
    )
```

Но это **отдельные инструменты протокола**: клиент-модель видит 4 инструмента,
у каждого своя схема параметров (проверено на живой реализации):

| Инструмент | Схема параметров (`inputSchema`) |
|---|---|
| `get_vacancy` | `{"id": {"type": "integer"}}` — обязательный |
| `get_employer` | `{"id": {"type": "integer"}}` — обязательный |
| `vacancy_app` | пустая — параметров нет |
| `employer_app` | пустая — параметров нет |

## 3. Параметры: кто, как и через что их передаёт

### 3.1. Через обычный API (JSON)

Любой MCP-клиент вызывает backend-инструмент, передавая аргументы **JSON**:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "get_vacancy",
    "arguments": {"id": 138156968}
  }
}
```

### 3.2. Через UI (без JSON руками)

Пользователь **не пишет JSON**: он вводит значение в поле ввода. Дальше:

1. `Input(name="vacancy_id")` кладёт значение поля в состояние интерфейса под
   ключом `vacancy_id`.
2. В `arguments` кнопки написано `{"id": "{{ vacancy_id }}"}` — это **шаблонная
   подстановка** (interpolation): перед вызовом `{{ vacancy_id }}` заменяется
   текущим значением поля.
3. `CallTool` отправляет на сервер ровно тот же
   `tools/call` `{"name": "get_vacancy", "arguments": {"id": …}}`, что и в 3.1.

То есть UI — это удобная обёртка над тем же самым JSON-RPC-вызовом.

### 3.3. Почему у `vacancy_app` нет параметров

`vacancy_app` лишь **описывает интерфейс** (поле + кнопка). Ввод пользователя
живёт в состоянии этого интерфейса и подставляется в вызов backend-инструмента,
а не передаётся в параметрах `vacancy_app`. Поэтому схема пустая — и это
нормально.

## 4. Кто кого вызывает: видимость (visibility)

«Какие-то функции вызываются, какие-то нет» — это про **видимость**:

| Декоратор | Видимость по умолчанию | Виден модели (LLM) | Виден UI (кнопкам/формам) |
|---|---|---|---|
| `@app.ui()` | `["model"]` | ✅ | ❌ (отклоняется) |
| `@app.tool()` | `["app"]` | ❌ | ✅ |
| `@app.tool(model=True)` | `["app", "model"]` | ✅ | ✅ |

В hh-mcp `get_vacancy` и `get_employer` помечены `model=True`, поэтому их видит
и модель, и UI. `vacancy_app`/`employer_app` видны только модели.

Следствия:

- **Модель** может вызывать все 4 инструмента: открыть панель (`vacancy_app`)
  или сразу получить Markdown (`get_vacancy`).
- **UI** (панель в браузере) может вызывать только backend-инструменты —
  через `CallTool`. Сам себя он вызвать не может.
- Если убрать `model=True`, инструмент исчезнет из списка модели, но останется
  доступным кнопкам UI.

> ⚠️ Видимость — **не** граница безопасности: инструмент остаётся вызываемым
> по прямому `tools/call` любым клиентом, знающим его имя. Защита — на уровне
> авторизации/валидации сервера.

## 5. Есть ли API? Как вызвать hh-mcp из другого приложения

**API есть** — это стандартный MCP-сервер по протоколу JSON-RPC, ничего
«приложенческого» в транспорте нет. Режим приложений меняет только **содержимое
ответа**, не способ вызова.

### 5.1. Точка входа

По умолчанию (transport `http`, см. `fastmcp.json`):

```
http://127.0.0.1:8000/mcp
```

### 5.2. Список инструментов

```
POST /mcp
```

```json
{"jsonrpc": "2.0", "id": 1, "method": "tools/list", "params": {}}
```

Ответ содержит 4 инструмента (2 backend с параметром `id`, 2 UI без параметров).

### 5.3. Вызов backend-инструмента

```json
{"jsonrpc": "2.0", "id": 2, "method": "tools/call",
 "params": {"name": "get_vacancy", "arguments": {"id": 138156968}}}
```

Ответ — `isError: false` и Markdown страницы.

### 5.4. Вызов UI-инструмента

```json
{"jsonrpc": "2.0", "id": 3, "method": "tools/call",
 "params": {"name": "vacancy_app", "arguments": {}}}
```

Ответ — `isError: false`, текст `[Rendered Prefab UI]` и поле
`structured_content` с деревом компонентов (`{"$prefab": …, "view": …}`).
Это дерево рендерит **хост, поддерживающий приложения** (FastMCP dev-UI,
Prefab-хост). Обычный JSON-клиент получит тот же ответ, но без рендера —
полезной нагрузки (текста вакансии) здесь нет, её даёт `get_vacancy`.

### 5.5. Итог

| Нужно | Инструмент | Аргументы |
|---|---|---|
| Получить Markdown вакансии | `get_vacancy` | `{"id": int}` |
| Получить Markdown работодателя | `get_employer` | `{"id": int}` |
| Открыть интерактивную панель | `vacancy_app` / `employer_app` | `{}` |

### 5.6. Формат ответа backend-инструмента: «две одинаковые строки» — это норма

Полный JSON-ответ `tools/call` на `get_vacancy` содержит **один и тот же текст
дважды**:

```json
{
  "content": [{"type": "text", "text": "# Ведущий программист 1С\n…"}],
  "structuredContent": {"result": "# Ведущий программист 1С\n…"}
}
```

Это **штатное поведение fastmcp 4.x** (механизм `wrap-result`), а не дубликат
данных:

- `content[0].text` — текст для обычных MCP-клиентов (LLM, curl и т.п.);
- `structuredContent.result` — та же строка, обёрнутая в `{"result": …}`
  для клиентов с поддержкой apps/structured content; fastmcp-клиент
  автоматически разворачивает её обратно (`.get("result")`).

Сам Markdown внутри **не задвоен**: заголовок `## About the employer`
встречается один раз (проверено на fastmcp 4.0.11 / prefab-ui 0.20.2).

### 5.7. Тост «Готово» / «Ошибка» — что они значат

В dev-UI (панель операций сервера слева) каждый вызов показывается полностью —
аргументы и JSON-ответ. Тост в UI-панели лишь подтверждает исход:

- **«Готово»** (`on_success`) — `tools/call` завершился без ошибок. Сам
  результат в панели не рисуется: он живёт в ответе вызова (см. 5.6) и виден
  в панели операций сервера.
- **«Ошибка»** (`on_error`) — инструмент бросил `ToolError`; тост показывает
  **текст ошибки** через подстановку `{{ $error }}` (штатный механизм prefab:
  рендерер кладёт сообщение ошибки вызова в scope обработчика). Например, для
  несуществующего ID (`5690403552`) hh.ru отвечает 404, и пользователь увидит
  `HTTP 404 …` вместо глухого «Ошибка».

## 6. Генеративный интерфейс (Generative UI) — отдельная вещь

Не путать `FastMCPApp` (то, что в hh-mcp) с **Generative UI**
([gofastmcp.com/apps/generative](https://gofastmcp.com/apps/generative)):

- `FastMCPApp` — разработчик **заранее пишет** компоненты (`@app.ui()`),
  форма фиксированная.
- Generative UI — **модель сама пишет код интерфейса на ходу**: инструмент
  `generate_prefab_ui` принимает Python-код (строку), выполняет его в песочнице
  (Pyodide) и рендерит результат как приложение.

hh-mcp использует первый вариант. Оба живут поверх Prefab — библиотеки
компонентов (`prefab_ui`), которую рендерит хост в sandboxed iframe.

## 7. Поток запроса целиком

```
Внешнее приложение / модель                hh-mcp (FastMCPApp)
─────────────────────────                  ─────────────────────
tools/call vacancy_app  ──►  отдать дерево компонентов (UI)
                                  │
                                  ▼
tools/call get_vacancy {id}  ──►  fetch_as_markdown(hh.ru/vacancy/{id})
                                  │
                                  ▼
                            Markdown-текст  ──►  ответ клиенту

UI-режим (браузер):
пользователь вводит id → кнопка → CallTool("get_vacancy",
аргументы {"id": "<введённое значение>"}) → тот же tools/call
```

## 8. Типичные заблуждения (коротко)

1. **«Параметры надо передавать JSON»** — да, на уровне протокола всегда JSON
   (`arguments`). В UI пользователь передаёт их не руками, а через поля форм и
   подстановку `{{ }}`.
2. **«Какие-то функции вызываются, какие-то нет»** — это видимость
   (`model`/`app`), см. таблицу в разделе 4.
3. **«Непонятно, есть ли API»** — есть: обычный MCP JSON-RPC на `/mcp`; все
   4 инструмента список видны в `tools/list`.
4. **«UI-инструмент принимает мои параметры?»** — нет: параметры он не
   принимает, он только открывает интерфейс; данные передаются через
   backend-инструмент (`get_vacancy`/`get_employer`).
5. **«Тул возвращает JSON с двумя одинаковыми длинными строками»** — это
   `content[0].text` и `structuredContent.result` (механизм `wrap-result`
   fastmcp 4.x). Данные не дублируются — сам Markdown один; дублируется только
   его сериализация в ответе (см. § 5.6).
6. **«Нажал кнопку — всплыло „Готово“ (okay), а результата не видно»** — это
   `on_success`-тост; результат не рисуется в самой панели, он в ответе вызова
   и в панели операций сервера dev-UI (см. § 5.7).
