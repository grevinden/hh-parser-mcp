## 2. SECURITY

### S1. SSRF-guard не блокирует IP-литералы и приватные адреса — **[VERIFIED] HIGH**

`src/hh_mcp/fetch/guards.py` (`UrlGuard.validate`) проверяет **только строку hostname** по 5 правилам
(схема, userinfo, пустой хост, `localhost`/`.localhost`, `.local`). Разрешения IP-адресов,
DNS-резолва и диапазонов адресов нет вовсе.

Проб (фактический вывод):
```
REJECT https://localhost/test                     [SSRError: localhost is not allowed]  ← требование AGENTS.md выполнено
PASS   http://127.0.0.1/
PASS   http://169.254.169.254/latest/meta-data/   ← cloud metadata
PASS   http://[::1]/
PASS   http://10.0.0.1/                           ← RFC1918
PASS   http://0.0.0.0/
PASS   http://2130706433/                         ← decimal-encoded 127.0.0.1
PASS   http://metadata.google.internal/
```

Формальный критерий AGENTS.md (`https://localhost/test` должен падать) выполняется,
но фактическая защита от SSRF отсутствует: любой вызывающий MCP-клиент может заставить
сервис обратиться к loopback/metadata-адресу (например, `http://169.254.169.254/...`
в облаке — кража учётных данных инстанса).

**Минимальный механизм исправления:** блокировать IP-литералы (включая десятичные/октетные формы и `[::1]`),
резолвить DNS и проверять полученный адрес против приватных диапазонов (SSRF-классика), либо
ограничить хосты allowlist'ом (только `hh.ru` + поддомены — сервис всё равно тянет только hh.ru).

### S2. Цель редиректа не ревалидируется — **[VERIFIED] HIGH**

`HttpxTransport._build_client` включает `follow_redirects=True`, но guard вызывается **только
один раз — на входе** (`FetchService.fetch_page → self._guard.validate(url)`). По цепочке
редиректов guard не проходит.

Эмпирическое подтверждение (через DI-хук `client_factory` + `httpx2.MockTransport`):
```
entry URL:  http://public.example/x   → guard PASS (публичный хост)
302 →       http://127.0.0.1:9/internal
requested URLs: ['http://public.example/x', 'http://127.0.0.1:9/internal']
body: b'SECRET-CONTENT'
```
То есть публичный хост, отдающий 302 на localhost/приватную сеть, обходит guard полностью
(в сочетании с S1 — сквозной обход).

**Минимальный механизм:** либо `follow_redirects=False` + ручной цикл с `guard.validate()` на каждый hop,
либо `event_hooks`/`httpx`-хук, валидирующий `request.url` на каждый запрос при `max_redirects` ≤ 10.

### S3. Секрет в рабочем дереве, не защищён gitignore — **[VERIFIED] HIGH (процесс)**

- Файл `.env.py` содержит параметры подключения Redis (`REDIS_HOST/PORT/USER/PASS/DBID`, `_USE_CACHE`).
  **Значение секрета намеренно не воспроизводится** (протокол §10).
- `git check-ignore -v .env.py` → **rc=1** — файл НЕ игнорируется (`.gitignore` существует,
  создан сегодня, но покрывает только `__pycache__/.venv/.idea/...`).
- Индекс: `.env.py` staged как **пустой файл** (`A`), содержимое — только в worktree (`M`).
  Один `git add -A` — и секрет окажется в коммите.
- Имя `.env.py` нестандартно: инструменты, читающие `.env`, его не увидят; риск «забыть» при
  обычном добавлении `.env`.

**Рекомендация:** добавить `.env`/`.env*.py` в `.gitignore`, вынести секреты в
неверсионируемый `.env`, значение ротировать (секрет считается скомпрометированным для целей репозитория).

**Дополнительно [VERIFIED] MEDIUM:** `server.py` staged **пустым** (0 байт), а staged-версия
`fastmcp.json` тоже пустая — при этом unstaged `fastmcp.json` ссылается
`"source": {"path": "server.py", "entrypoint": "mcp"}` → деплой через fastmcp упадёт
с ImportError/AttributeError на пустом модуле **[INFERRED]**.

## 3. CORRECTNESS

### C1. Sanitizer молча удаляет весь контент после void-шумового элемента — **[VERIFIED] HIGH (латентно)**

`src/hh_mcp/fetch/html.py`, `_ReconstructingHtmlParser.handle_starttag`:
проверка шума (`self._noise.is_noise(...) → _push_suppressed()`, строка ~197) выполняется
**раньше** проверки void-элементов (строка ~226). `NoisePolicy.remove_elements` содержит `"input"`,
а `<input>` — void-элемент: **end-tag никогда не придёт**, `False` остаётся в `_stack` навсегда →
`_inside_noise == True` → весь последующий документ подавлен.

Проб (воспроизводимо):
```
input-then-content:  '<main><input type="hidden" name="csrf"><p>IMPORTANT TEXT</p></main>'
  → html='<main>'                       ← TEXT ПОТЕРЯН (LOST)
self-closing-input:  '<main><input type="hidden"/><p>IMPORTANT TEXT</p></main>'
  → html='<main><p>IMPORTANT TEXT</p>'  ← OK (handle_startendtag, push не делается)
no-input-baseline:   → OK
```

**Почему сейчас не выстреливает на hh.ru [VERIFIED]:** живые страницы отдают inputs
самозакрывающимися — vacancy `138156968`: 8/8 `<input>` в `<main>` имеют `/>`;
employer `11620617`: 0 `<input>` в `<main>`. Тип HTML5 без слэша (`<input ...>`) — валидный
и распространённый: любой другой сайт/новая вёрстка hh.ru → пустой вывод без ошибки.

**Минимальное исправление:** в `handle_starttag` для noise-элементов из `_VOID_ELEMENTS`
удалять поддерево без push в `_stack` (или сдвигать noise-проверку после void-ветки).

### C2. Внутренние ссылки hh.ru не удаляются — критерий приёмки нарушен — **[VERIFIED] HIGH**

AGENTS.md (Test cases): «Ожидаем чистый markdown … **без внутренних ссылок**, внешние ссылки сохраняются».

Живой прогон:
```
get_employer 11620617 → internal_links=6:
  https://kolomna.hh.ru/vacancy/138205968 … 137092216 (все 6)
get_vacancy 138156968 → internal_links=1
```
Функция `remove_internal_links` реализована в `src/hh_mcp/fetch/enrich.py`,
но модуль **untracked (`??`)** и **никуда не подключён**: `fetch/__init__.py` его не экспортирует,
`app.py`/`orchestrator.py` не импортируют. Связанные константы `EMPLOYER_FETCH_MAX_CHARS`
(config.py) и `embed_employer_card` — тоже не используются (dead code).

**Статус:** похоже на WIP параллельного агента (файл новый). Как есть сейчас — критерий приёмки не выполнен.

### C3. Лимит тела ответа применяется после полной загрузки — **[VERIFIED] MEDIUM**

`transport.py`: `content = response.read()` → затем `if len(content) > cfg.max_body_bytes: raise`.
Стриминга/пообчайтового счётчика нет: сервер может отдать много ГБ — всё буферизуется в RAM,
лимит сработает только после. Риск памяти (DoS) при недружелюбном ответе.

**Минимальное исправление:** `client.stream(...)` + нарезка чтения с проверкой суммарного размера
на каждой порции (или заголовок `Content-Length` как ранний reject).

### C4. Ложное сообщение об ошибке «too large» — **[VERIFIED] LOW**

`app.py::_tool_error`: `ResponseTooLargeError → ToolError(f"Response too large > {MAX_CHARS}")`,
но реальный лимит этой ошибки — `max_body_bytes` = 4 MiB **байт**, а `MAX_CHARS = 120_000` —
лимит символов Markdown (другая ось). Сообщение вводит пользователя в заблуждение.

### C5. `base_url` для резолва ссылок — сырая строка, а не нормализованная — **[VERIFIED] LOW**

`FetchService.fetch_as_markdown`: `validated_url = guard.validate(url)` выполняется внутри
`fetch_page`, но sanitizer/`resolve_relative_links` и converter получают **исходный** `url`
(`base_url=url`). При нестандартной форме URL (регистр хоста, пустой query и т.п.) резолв
ведётся по «ненормализованной» базе. Формально — рассинхрон guard-нормализации и использования.

### C6. `clean_employer_markdown`: «first H1» — на деле первый заголовок любого уровня — **[VERIFIED] LOW**

`enrich.py`: переменная `first_h1_seen` устанавливается при `_HEADING_RE.match` — то есть
при первом `## H2`/`### H3` тоже, и он **выбрасывается** как «имя компании». На странице,
начинающейся с H2, карточка потеряет первый заголовок. Сейчас маскируется тем, что
`fetch_as_markdown` всегда префиксует `# title`.

### C7. Обработка «специальных» timeout — **[INFERRED] LOW**

`FetchService.fetch_page`: `timeout <= 0` молча заменяется на `PUBLIC_MIN_TIMEOUT` (1.0);
`NaN` проходит оба сравнения → `RequestConfig.__post_init__` бросит `ValueError("timeout: …")`,
который **не ловится** маппингом `_fetch_markdown` (ловит только `SSRError/InvalidURLError/FetchError`)
→ внутренняя ошибка MCP вместо дружелюбного `ToolError`. Из `app.py` недостижимо (константа 30),
достижимо при прямом вызове API с `float("nan")`.

### C8. Декодирование только UTF-8 — **[VERIFIED] LOW (сейчас работает)**

`orchestrator.py`: `html_bytes.decode("utf-8-sig")` → `ParseError` на любой другой кодировке
(например, windows-1251). Живые страницы hh.ru сегодня в UTF-8 (проверено прогоны OK),
но fallback'а на charset из HTTP-заголовка нет.

### C9. Fallback при `RecursionError` возвращает HTML как «Markdown» — **[VERIFIED] LOW**

`converter.py`: `except RecursionError … return MarkdownResult(markdown=html, title=None)` —
возвращается санированный **HTML-документ**, а не Markdown (докстринг обещает «plain-text fallback»).
Контракт «чистый markdown» нарушается в этом сценарии (санированный HTML — приемлемо по шуму,
но не по формату).

## 4. RELIABILITY / ROBUSTNESS

### R1. `devapp.py` практически без тестов — **[VERIFIED] MEDIUM**

534 строки REST/UI-слоя; в `tests/` импорт `hh_mcp.devapp` встречается **один раз**
(`test_mcp_app.py:477`, create_app). Не покрыты: `/api/status`, `/api/mcp`,
`POST /api/mcp/call` (валидация тела, классификация 503/502 через `_connection_error`),
`McpBackend` one-shot lifecycle, `_ClientProxy`. `__main__.dev_mode` (signal-handling,
два uvicorn-сервера, `capture_signals = nullcontext`) — тоже без тестов (парсер покрыт).

### R2. Прямой вызов транспорта с невалидным URL — **[VERIFIED] LOW**

`HttpxTransport.fetch`: `host = str(httpx.URL(url).host)` — **до** `try`-блока; при
некорректном URL выбросит незахваченный `httpx.InvalidURL` (не доменный `FetchError`).
В штатном пути guard предшествует → не достижимо; достижимо при DI/прямом использовании.

### R3. Деплой-конфиг указывает на пустой модуль — **[VERIFIED конфиг / INFERRED падение] MEDIUM**

`fastmcp.json` (worktree): `source.path = "server.py"`, `entrypoint = "mcp"`; `server.py` — 0 байт.
Запуск через fastmcp-деплой упадёт. Файлы staged в пустом виде (см. §7).

### R4. Десинхрон стека подавления при mismatched end-tags — **[VERIFIED] LOW (by design)**

`handle_endtag` делает `self._stack.pop()` **без проверки имени тега**: несогласованный HTML
может закрыть не тот кадр (лишний вывод или подавление). Документировано как lenient-
поведение; риск принять во внимание при работе с «грязным» контентом.

## 5. PERFORMANCE (низкий приоритет)

- **P1 [VERIFIED] LOW:** `NoisePolicy.is_noise` внутри цикла `for name in attrs` на каждый
  атрибут заново строит `tuple(self.remove_attrs_prefix)`; префиксы классов не про-`casefold`ены
  заранее (сравнение делается на каждой итерации токена). На больших страницах — лишние
  аллокации в горячем пути санитайзера.
- `HttpxTransport` создаёт `httpx.Client` на каждый запрос (без пула) — осознанный
  trade-off (задокументирован в докстринге), учитывать при росте нагрузки.
